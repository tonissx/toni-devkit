## See it in action

### From a log error to the database blocker, in one click

A timeout shows up in `server.log`. Instead of opening SSMS and guessing, **"O que o banco fazia?"** ("What was the
database doing?") opens the SQL Server history at that exact time. Here, a forgotten transaction (`BEGIN TRAN` with no
`COMMIT`) is holding the other sessions.

<img src="docs/img/log-to-db.gif" alt="From a timeout error in server.log to the Database history showing the session blocking the others" width="760" />

<sub>Fictional data, generated by script (`npm run docs:capture`).</sub>

1. **Logs** opens `server.log`, groups the 6 timeouts into **one problem**, and shows the spike on the timeline.
2. **O que o banco fazia?** jumps to **Database** at the same minute, using the history the monitor recorded.
3. The incident shows the **blocking tree**: the idle session holding the open transaction on top, and who was waiting.

## Installation

[**⬇ Download the latest stable release**](https://github.com/tonissx/toni-devkit/releases/latest). The badge at the top
shows the version number. No account needed, and no Node, Python or database driver to install.

| System | File in the release | What it is |
| --- | --- | --- |
| **Windows 10/11 (x64)** | `Toni Devkit Setup x.y.z.exe` | Installer (recommended): pick the folder, get a shortcut, update from inside the app |
| Windows | `Toni Devkit x.y.z.exe` | Portable: runs from any folder, no install |
| macOS | `.dmg` | Built by CI, less used and tested |
| Linux | `.AppImage` | Built by CI, less used and tested |

> On GitHub the file name may show dots instead of spaces (`Toni.Devkit.Setup.x.y.z.exe`).

### Requirements

- **Windows 10 or 11, 64-bit.** This is where Devkit is used and tested every day; macOS and Linux work, with less coverage.
- **Nothing else to install**: the SQL formatter (Pyodide) and the SQL Server driver (`tedious`) ship inside the app.
- **SQL Server 2016 or newer**, only if you use the **Database** tool. Every other tool works without any server.
- **Network**: only to check for updates and, if you turn it on, cloud AI. Everything else runs locally.

### Code signing: current status

**The installer is not digitally signed yet** (no code-signing certificate). On first run, Windows SmartScreen may show
"Windows protected your PC": click **More info → Run anyway**.

Since there is no signature, you can verify where a download came from in other ways. Everything below applies to
releases published after CI started producing these files; older releases have no `SHA256SUMS.txt` and no attestation.

1. **Download only from the official releases page**: `github.com/tonissx/toni-devkit/releases`.
2. **Check the SHA-256 hash** against the `SHA256SUMS.txt` of the same release:

   ```powershell
   Get-FileHash .\Toni.Devkit.Setup.x.y.z.exe -Algorithm SHA256
   # the value must match this file's line in SHA256SUMS.txt
   ```

3. **Check the build provenance attestation** (proof that the file came out of this repository's release workflow,
   unmodified afterwards). Requires the [GitHub CLI](https://cli.github.com/):

   ```bash
   gh attestation verify "Toni.Devkit.Setup.x.y.z.exe" -R tonissx/toni-devkit
   ```

4. **Or build it yourself** (below). The code is MIT-licensed and the whole CI lives in `.github/workflows/`.

### Build from source

Node 20+:

```bash
git clone https://github.com/tonissx/toni-devkit.git
cd toni-devkit
npm install
npm start
```

| Command | What it does |
| --- | --- |
| `npm run dev` | Like `start`, with DevTools open |
| `npm test` | All tests, in Node, no Electron |
| `npm run dist` | Windows installer (NSIS) and portable in `dist/` |
| `npm run dist:mac` / `dist:linux` | `.dmg` / AppImage |

## Why it exists

Every day we open one website to format SQL, another to compare two texts, another to read a JSON. Each tool here runs
**on your computer**, sends nothing out, and all of them are reachable from a command palette (`Ctrl+Alt+Space`) from
anywhere in the system.

## What's inside

| | Tool | In one sentence |
| --- | --- | --- |
| 🧮 | **SQL Formatter** | Same engine as sqlformat.org (`sqlparse` on Pyodide), offline, with risk warnings (`UPDATE` without `WHERE`…) |
| 🧾 | **XML Formatter** | vscode-xml style formatting, with well-formedness validation |
| 🔍 | **Diff Checker** | Side by side or unified, in-line highlighting, merge block by block |
| 🕸️ | **JSON Visualizer** | JSON as graph, tree, YAML or CSV; JSONPath; generates TypeScript, C# and JSON Schema types |
| 🌿 | **Git** | Visual UI with graph, hunk staging, merge preview, visual rebase, blame, bisect and **undo** |
| 📜 | **Logs** | Big logs (Fluig/JBoss, JSON lines, IIS, Nginx/Apache) with filters, grouped errors, charts and live tailing |
| 🗄️ | **Database** | SQL Server monitor: who blocks whom, slow queries, deadlocks and health, live and from history |
| 🧭 | **SQL Visualizer** | SQL as a graph without running anything: ER diagram (DDL, metadata or straight from the server), big-schema explorer, query lineage and execution plans (`.sqlplan`) |
| 📝 | **Notes** | Markdown with `[[links]]`, tags, graph, snippets, tasks and sticky notes |
| 🔐 | **Vault** | Local vault (AES-256-GCM) with a master password and self-clearing copy |
| 🎮 | **DevCore** | An optional idle game, with DevPets you discover by using Devkit itself |
| ✦ | **AI (optional)** | Off by default. Local via Ollama or cloud via Claude; nothing is applied without a click |

## Highlights

### Git for people who get stuck on the tricky operations

Rebase, conflicts and cherry-pick without memorizing commands. Hovering any action shows the **equivalent git command**,
and before any operation that rewrites history or discards work, Devkit writes a restore point to
`refs/devkit/backup/…`. **Nothing is lost, and everything has Undo.**

<img src="docs/img/git-graph.gif" alt="Commit graph, visual rebase and conflict resolution" width="760" />

- History graph and hunk staging (`git add -p` without memorizing anything)
- Merge with a **preview** of the files that will conflict
- Conflict editor with Mine / Theirs / Both per block
- Interactive rebase by drag and drop
- Blame, "when did this text appear" search, guided bisect
- Time machine over the reflog

### JSON as a graph

<img src="docs/img/json-graph.png" alt="JSON Visualizer showing a document as a node graph" width="760" />

Editor on the left and, on the right, the document as graph, tree, YAML or CSV. Search by text or JSONPath, **Fix**
(comments, trailing commas, single quotes) and PNG or SVG export.

### Database: who is blocking SQL Server

<img src="docs/img/db-blocking.png" alt="Database, History tab: blocking incident with the session tree and each session's SQL" width="760" />

Connects to the server and shows, every few seconds, the **blocking tree** (the session holding the others at the top,
including the classic forgotten transaction: idle with `BEGIN TRAN` still open), the active sessions and what they are
waiting for, and per-session details with the SQL, the plan and **Kill** (with confirmation). In the background it
records a **history**: you can go back to any moment of the last hours or days and see the snapshot of the blocking,
the long query or the deadlock.

- **Light enough for production**: system views only, dirty reads, short timeout and low deadlock priority; measured at
  ~4 ms of CPU per cycle. The password lives in the **Vault**
- **Deadlocks** read from `system_health`, drawn (who waits × who holds, victim highlighted) and saved as `.xdl`
- Most expensive **queries** (plan cache or Query Store) and **Health**: filling log and why, disk, backups, failed
  jobs, connections per program and suggested indexes
- Integrates with **Logs**: on a timeout error in `server.log`, "O que o banco fazia?" opens the history at that time

### Logs: the right error in seconds

<img src="docs/img/logs.png" alt="Logs: timeout errors grouped as one problem, with the stack trace and the 'what was the database doing?' button" width="760" />

Opens logs of hundreds of MB in seconds, including over network paths (`\\server\logs`), and follows the file **live**
like `tail -f`. Stack traces become a single entry, the same failure with different ids and times becomes one grouped
**problem**, and the timeline shows the error spikes; drag on it to filter the interval.

- Formats detected automatically: Fluig/JBoss, JSON lines, IIS, Nginx/Apache, log4j/Spring and plain text
- Folders of rotated logs (`server.log.2026-10-10`, `app.log.1`, `.gz`) become a single log
- Search with `level:error+ logger:fluig status:5xx "phrase" /regex/ -hide`, saved filters, `n`/`N` for the next error
- Errors-per-minute charts and, for access logs, status, p50/p95 latency and slowest endpoints
- Copy without secrets and, with AI on, **explain the error** (passwords and tokens are stripped before sending)

### Global command palette

<img src="docs/img/palette-search.png" alt="Palette searching across tools, notes and links" width="760" />

`Ctrl+Alt+Space` opens the palette over any app, even with Devkit minimized. It searches commands, notes, snippets and the
web. It also has **Quick Note** (`Alt+Q`), **quick links** with aliases (`ticket` + `Tab` + `1234` opens the ticket) and
SQL/XML formatting straight from the clipboard.

## Principles

- **Offline by default.** No account, no telemetry. The network is only used when you turn on cloud AI or check for updates.
- **Your data is files.** Notes are `.md` in `Documents\Devkit Notes`; everything else lives in `%APPDATA%\Toni Devkit`.
- **The Vault never goes to the AI.** Notes carry the secret's reference, never its value. Notes tagged `privado` also
  never leave your computer.
- **Nothing happens unless you ask.** AI, applying changes and destructive operations all need a click, and almost everything undoes.

## How it's built

Electron + React, with the renderer bundled by esbuild. The engines (SQL, XML, Diff, JSON, Git, Logs, Database, Notes,
Vault, DevCore) are pure modules, tested in Node without opening a window. SQL runs `sqlparse` on Pyodide in a *worker
thread*, Logs index and filter in another one with the UI asking only for the visible lines, and Database talks to SQL
Server through `tedious` (a JavaScript driver, nothing native to install). The folder layout and how to add a new tool
are in the [full guide](docs/FEATURES.md#estrutura) (Portuguese).
